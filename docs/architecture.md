# AdLab 架构与阶段边界

## 分层

1. `app.py` 和 `src/adlab/ui/` 是界面层，只收集输入、展示解释和调用核心函数。
2. `src/adlab/config.py` 保存实验目录和阶段状态。导航与首页共用这一份数据。
3. `src/adlab/charts/` 将算法结果转换为 Plotly 图表，不负责计算实验指标。
4. 后续阶段在 `src/adlab/algorithms/` 放纯 Python 算法，在 `src/adlab/data/` 放合成数据与 SQLite 存取。
5. `tests/` 验证核心行为和算法边界；UI 再通过本地启动检查。

典型数据流：用户参数 → 输入校验 → 算法函数 → 结构化结果 → 图表与文字解读 → 可选的 SQLite 记录。

第三阶段的竞价输入由 `algorithms/auctions.py` 处理；`data/records.py` 为 A/B 与竞价分别建表，页面只负责调用算法与保存完整输入/输出。

第四阶段的 `data/ctr_synthetic.py` 生成合成曝光；`algorithms/ctr.py` 负责原始行划分、训练集内预处理、验证集选模型与测试集评估；`charts/ctr.py` 负责 ROC、概率分布和校准图。CTR 记录只保存生成配置与聚合指标，不保存逐行曝光或模型。

## 第一版 MVP

第一、二阶段组成已交付的 MVP：可启动的基础界面，以及完整的 A/B 测试实验室。未开发实验的页面明确显示“规划中”，不输出模拟结果。

## A/B 测试模块接口

输入为两组各自的独立随机分配用户数、点击数、转化数，以及实验周期。主指标可选 CTR 或每用户转化率；点击后 CVR 作为描述性指标。输出包含比例、相对提升、置信区间、检验方法和 p 值。样本量估算另接收基线率、最小可检测差异、显著性水平和目标功效。

每个算法模块的结果应带有假设和方法名称，以免界面把教学模拟写成真实平台效果。
