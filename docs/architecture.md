# AdLab 架构与阶段边界

## 分层

1. `app.py` 和 `src/adlab/ui/` 是界面层，只收集输入、展示解释和调用核心函数。
2. `src/adlab/config.py` 保存实验目录和阶段状态。导航与首页共用这一份数据。
3. `src/adlab/charts/` 将算法结果转换为 Plotly 图表，不负责计算实验指标。
4. 后续阶段在 `src/adlab/algorithms/` 放纯 Python 算法，在 `src/adlab/data/` 放合成数据与 SQLite 存取。
5. `tests/` 验证核心行为和算法边界；UI 再通过本地启动检查。

典型数据流：用户参数 → 输入校验 → 算法函数 → 结构化结果 → 图表与文字解读 → 可选的 SQLite 记录。

## 第一版 MVP

第一、二阶段组成 MVP：可启动的基础界面，以及完整的 A/B 测试实验室。第一阶段只交付基础结构。未开发实验的页面明确显示“规划中”，不输出模拟结果。

## A/B 测试模块接口计划

输入为两组各自的独立随机分配用户数、点击数、转化数，以及实验周期。主指标是每位用户点击率；点击后 CVR 作为描述性指标。输出包含 CTR、CVR、相对提升、置信区间、检验方法和 p 值。样本量估算另接收基线率、最小可检测差异、显著性水平和目标功效。

每个算法模块的结果应带有假设和方法名称，以免界面把教学模拟写成真实平台效果。
